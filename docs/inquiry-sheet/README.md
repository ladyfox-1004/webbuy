# 홈페이지 문의 → 구글 시트 + 메일 알림 설정하기

홈페이지 문의 폼으로 문의가 들어오면 구글 시트에 한 줄씩 쌓이고, 시트 주인 메일로 알림이 갑니다.
연락처가 이메일이면 고객 답장 초안도 Gmail 임시보관함에 만들어 둡니다(자동 발송은 하지 않습니다).
개발 지식 없이 순서대로 따라 하면 됩니다. 처음 한 번만 하면 되고, 20분 정도 걸립니다.

> **알아두기**
> 문의의 **원본은 홈페이지 DB(Supabase `inquiries` 테이블)** 입니다. 구글 시트는 **알림용 사본**입니다.
> 시트 연결이 끊기거나 설정을 안 해도 문의는 DB에 정상 저장됩니다.

---

## 준비물

- 구글 계정 (알림 메일은 이 계정으로 옵니다)
- 이 폴더의 `Code.gs` 파일
- 홈페이지 저장소 폴더를 열 수 있는 컴퓨터 (마지막 단계에서 명령어 두 줄을 입력합니다)

---

## 1단계. 구글 시트 새로 만들기

1. [sheets.new](https://sheets.new) 에 접속하면 빈 시트가 바로 만들어집니다.
2. 왼쪽 위 "제목 없는 스프레드시트"를 눌러 이름을 바꿉니다. 예: `홈페이지 문의`

## 2단계. Apps Script 에 코드 붙여넣기

1. 시트 위쪽 메뉴에서 **확장 프로그램 → Apps Script** 를 누릅니다. 새 탭이 열립니다.
2. 편집기에 원래 있던 코드(`function myFunction() { ... }`)를 **전부 지웁니다**.
3. 이 폴더의 `Code.gs` 내용을 **전부 복사해서 붙여넣습니다**.
4. 위쪽 디스크 모양 **저장** 버튼(또는 `Ctrl + S`)을 누릅니다.
5. 왼쪽 위 "제목 없는 프로젝트"를 눌러 이름을 정해도 좋습니다. 예: `문의 알림`

## 3단계. 비밀 토큰(TOKEN) 만들고 넣기

토큰은 "우리 홈페이지만 이 시트에 글을 쓸 수 있게" 해 주는 비밀번호입니다.

1. 긴 임의 문자열을 하나 만듭니다. **32자 이상**, 영문 대소문자와 숫자를 섞어 주세요.
   - 쉬운 방법: 비밀번호 관리자(구글 비밀번호 관리자, 1Password 등)의 "비밀번호 생성" 기능으로 40자쯤 만듭니다.
   - 특수문자는 빼는 편이 붙여넣을 때 실수가 적습니다.
   - 이 값은 6단계에서 한 번 더 써야 하니 **메모장에 잠깐 적어 두세요** (작업이 끝나면 지웁니다).
2. Apps Script 편집기 왼쪽 메뉴의 **톱니바퀴(프로젝트 설정)** 를 누릅니다.
3. 맨 아래 **스크립트 속성 → 스크립트 속성 추가** 를 누릅니다.
4. 속성: `TOKEN` (대문자 그대로) / 값: 방금 만든 문자열 → **스크립트 속성 저장**.

## 4단계. 테스트 실행으로 권한 승인하기

1. 왼쪽 메뉴의 **`< >` (편집기)** 로 돌아옵니다.
2. 위쪽 실행 버튼 옆의 함수 선택 칸에서 **`testDoPost`** 를 고릅니다.
3. **실행** 을 누릅니다.
4. "승인 필요" 창이 뜨면 **권한 검토 → 내 구글 계정 선택** 을 합니다.
5. "Google에서 확인하지 않은 앱" 경고가 나오면 왼쪽 아래 **고급 → (프로젝트 이름)(으)로 이동(안전하지 않음)** 을 누릅니다.
   - 내가 직접 만든 스크립트라서 나오는 경고입니다. 다른 사람에게는 보이지 않습니다.
6. **허용** 을 누릅니다.
7. 확인할 것:
   - 시트 탭으로 돌아가면 아래쪽에 **"문의"** 시트가 새로 생기고, 머리글과 예시 한 줄이 들어가 있다.
   - 내 메일함에 **"[홈페이지 문의] 테스트 / 예시 회사 · ..."** 메일이 와 있다. (안 보이면 스팸함 확인)
   - Gmail **임시보관함**에 답장 초안이 하나 생겨 있다(받는 사람은 내 주소). 자세한 내용은 아래 "답장 초안 기능 켜기" 참고.
8. 확인했으면 예시 줄(2행)은 지워도 됩니다. **머리글(1행)은 지우지 마세요.**

## 5단계. 웹 앱으로 배포하고 URL 복사하기

1. 편집기 오른쪽 위 **배포 → 새 배포** 를 누릅니다.
2. "유형 선택" 옆 톱니바퀴를 눌러 **웹 앱** 을 고릅니다.
3. 아래처럼 설정합니다.
   - 설명: `홈페이지 문의` (아무거나)
   - 다음 사용자 인증 정보로 실행(실행 사용자): **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
     - "모든 사용자"여야 홈페이지 서버가 로그인 없이 보낼 수 있습니다. 토큰이 없으면 아무것도 기록되지 않으니 안전합니다.
4. **배포** 를 누릅니다. (권한을 다시 묻으면 4단계처럼 허용)
5. 나오는 **웹 앱 URL** (`https://script.google.com/macros/s/.../exec`) 을 **복사** 합니다.
6. 확인: 복사한 URL 을 브라우저 주소창에 붙여넣어 열면 화면에 `ok` 만 보이면 정상입니다.

## 6단계. 홈페이지 서버에 URL 과 토큰 등록하기

홈페이지 저장소 폴더에서 터미널(명령 프롬프트)을 열고 아래 두 줄을 **한 줄씩** 실행합니다.

```
npx wrangler secret put INQUIRY_SHEET_WEBHOOK_URL
npx wrangler secret put INQUIRY_SHEET_TOKEN
```

- 첫 번째 명령에서 값을 물으면 → 5단계에서 복사한 **웹 앱 URL** 을 붙여넣고 Enter.
- 두 번째 명령에서 값을 물으면 → 3단계에서 만든 **TOKEN 과 똑같은 문자열** 을 붙여넣고 Enter.
- 붙여넣어도 화면에 글자가 안 보일 수 있습니다. 정상입니다.
- 로그인하라는 안내가 나오면 Cloudflare 계정으로 로그인한 뒤 다시 실행합니다.

등록이 끝났으면 메모장에 적어 둔 토큰은 지웁니다.

## 7단계. 홈페이지 다시 배포하고 테스트하기

1. 평소 하던 방법으로 홈페이지를 다시 배포합니다.
2. 홈페이지 문의 폼에서 테스트 문의를 하나 보냅니다.
3. 시트에 새 줄이 생기고 알림 메일이 오면 끝입니다.

---

## Code.gs 를 고쳤을 때 (URL 그대로 유지하기)

코드를 고친 뒤 **"새 배포"를 다시 누르면 URL 이 바뀝니다.** 그러면 6단계를 다시 해야 합니다.
URL 을 그대로 두려면 이렇게 하세요.

1. 코드 수정 → 저장
2. **배포 → 배포 관리**
3. 기존 배포를 고르고 오른쪽 위 **연필(수정)** 아이콘
4. 버전: **새 버전** 선택 → **배포**

## 답장 초안 기능 켜기(기존 사용자용)

문의 연락처가 이메일이면, 고객에게 보낼 답장 초안이 내 Gmail **임시보관함**에 자동으로 만들어집니다.
초안만 만들고 **고객에게 저절로 보내지는 메일은 없습니다.** 내용을 확인한 뒤 직접 보내주세요.
연락처가 전화번호면 초안 대신, 알림 메일 맨 위에 "전화로 연락이 필요한 문의입니다"와 짧은 응대 순서가 붙습니다.
이미 시트 알림을 쓰고 계시다면 아래 순서대로 한 번만 바꾸면 됩니다.

1. 이 폴더의 새 `Code.gs` 내용을 **전부 복사**합니다.
2. Apps Script 편집기에서 기존 코드를 **전부 지우고** 붙여넣습니다.
3. **저장**(`Ctrl + S`)을 누릅니다.
4. 함수 선택 칸에서 **`testDoPost`** 를 고르고 **실행** 을 누릅니다.
5. "승인 필요" 창이 다시 뜹니다. 초안을 만들려면 **Gmail 권한이 새로 필요**하기 때문입니다.
6. 4단계 때처럼 **권한 검토 → 내 계정 → 고급 → (프로젝트 이름)(으)로 이동 → 허용** 을 누릅니다.
7. Gmail 왼쪽 메뉴의 **임시보관함** 을 엽니다.
8. "[에이아이솔루션] 테스트 / 예시 회사님 문의 잘 받았습니다" 초안이 있으면 성공입니다.
9. 테스트 초안의 받는 사람은 **내 주소**입니다(예시 주소로 가지 않습니다). 확인 후 초안은 지워도 됩니다.
10. 알림 메일 맨 위에 "Gmail 임시보관함에 답장 초안을 만들어 두었습니다" 한 줄이 있는지도 봅니다.
11. 이제 실제 홈페이지에 반영합니다. **배포 → 배포 관리** 를 누릅니다.
12. 기존 배포를 고르고 오른쪽 위 **연필(수정)** 아이콘을 누릅니다.
13. 버전에서 **새 버전** 을 고르고 **배포** 를 누릅니다.

> **주의:** **"새 배포"를 누르면 웹 앱 URL 이 바뀝니다.**
> 그러면 홈페이지가 예전 주소로 보내게 되어 6단계를 다시 해야 합니다.
> 꼭 "배포 관리 → 연필 → 새 버전"으로 하세요.
> 이 방법으로 하면 URL 이 그대로라 홈페이지는 다시 배포하지 않아도 됩니다.

**초안을 보내기 전에 확인할 것**
- 고객이 적은 내용은 꾸미지 않고 그대로 옮겨 적었습니다. 내용이 길면 앞 300자만 들어갑니다.
- 초안에는 가격·기간·성과·회신 날짜를 약속하는 말이 없습니다. 보내기 전에 이런 말을 덧붙이지 않는 것이 안전합니다.
- 서명에 전화번호는 넣지 않았습니다. 필요하면 보내기 전에 직접 적어 주세요.

**초안 기능 끄기**
1. Apps Script 편집기 왼쪽 **톱니바퀴(프로젝트 설정)** → **스크립트 속성** 으로 갑니다.
2. **스크립트 속성 추가** → 속성 `DRAFT_REPLY` / 값 `off` → **저장** 합니다.
3. 다시 켜려면 `DRAFT_REPLY` 속성을 지우거나 값을 `on` 으로 바꿉니다.
4. 이 속성은 저장하는 즉시 적용됩니다. 다시 배포할 필요는 없습니다.

**초안이 안 생겨요**
- 알림 메일 맨 위에 "답장 초안 만들기 실패"가 보이면 Gmail 권한 승인이 안 된 경우가 많습니다. 위 4~6번을 다시 해 주세요.
- 연락처가 이메일 형식(예: `name@company.com`)이 아니면 초안을 만들지 않습니다.
- 코드를 바꾼 뒤 "새 버전"으로 배포하지 않았다면 예전 코드가 계속 돌고 있습니다(위 11~13번).

## 시트 열 설명

| 열 | 내용 |
| --- | --- |
| 접수 시각 | 한국 시간 기준 (예: 2026-10-07 14:30:05) |
| 이름/회사 | 고객이 입력한 이름 또는 회사명 |
| 연락처 | 전화번호 또는 이메일 |
| 예산 | 숫자로 쓰면 "3,000만 원"처럼, 글로 쓰면 그대로(예: 협의 필요). 비우면 "미입력" |
| 희망 론칭일 | 날짜(YYYY-MM-DD) 또는 "미정" |
| 필요 솔루션 | 고객이 고른 항목들 (쉼표로 구분) |
| 문의 주제 | 홈페이지의 특정 버튼으로 들어온 경우 그 주제 (예: 예약을 받고 싶다). 없으면 빈칸 |
| 내용 | 프로젝트 내용 본문 |
| 참고 링크 | 고객이 적은 참고 사이트 |
| 첨부 여부 | `있음(파일명)` / `업로드 실패(파일명)` / `없음`. 파일 자체는 홈페이지 저장소에 있습니다 |
| 출처 | 보통 `homepage`. 테스트 실행으로 생긴 줄은 `test` |

> "업로드 실패"는 고객이 파일을 첨부했지만 저장소 업로드가 안 된 경우입니다.
> 고객 화면에는 "contact@ai-solution.co.kr 로 보내주세요"라는 안내가 나갑니다.

## 문제 해결

**메일이 안 와요**
- 스팸함·프로모션함을 확인하세요.
- 4단계 권한 승인을 끝까지 했는지 확인하세요. 편집기에서 `testDoPost` 를 다시 실행해 보면 권한 창이 다시 뜹니다.
- 메일은 **스크립트를 만든 구글 계정**으로 갑니다. 다른 주소로 받고 싶으면 그 계정 Gmail 에서 자동 전달을 설정하세요.
- 구글 무료 계정은 하루에 보낼 수 있는 메일 수에 한도가 있습니다(보통 100통). 넘으면 메일만 빠지고 시트 기록은 됩니다.

**시트에 줄이 안 생겨요**
- **TOKEN 불일치**가 가장 흔합니다. 3단계 스크립트 속성의 `TOKEN` 값과 6단계 `INQUIRY_SHEET_TOKEN` 값이 한 글자도 다르지 않아야 합니다 (앞뒤 공백 주의). 헷갈리면 새 토큰을 만들어 두 곳 모두 다시 넣으세요.
- 속성 이름이 정확히 대문자 `TOKEN` 인지 확인하세요.
- **URL** 이 `/exec` 로 끝나는지 확인하세요 (`/dev` 로 끝나는 테스트 URL 은 안 됩니다).
- 배포 설정의 **액세스 권한이 "모든 사용자"** 인지 확인하세요. "Google 계정이 있는 모든 사용자"나 "나만"이면 안 됩니다.
- 코드를 고쳤는데 "새 버전"으로 배포하지 않았다면 예전 코드가 계속 돌고 있습니다(위 "Code.gs 를 고쳤을 때" 참고).
- 시크릿을 새로 넣었거나 바꿨다면 홈페이지를 다시 배포해야 반영됩니다.

**시크릿을 아직 안 넣었어요**
- 괜찮습니다. 시크릿이 없으면 홈페이지는 시트 전송만 건너뛰고, **문의는 DB 에 정상 저장**됩니다.

**시트 연결을 끊고 싶어요**
- `npx wrangler secret delete INQUIRY_SHEET_WEBHOOK_URL` 을 실행하거나, Apps Script 의 **배포 관리**에서 배포를 보관 처리하세요. 문의 접수에는 영향이 없습니다.

## 참고: 선택 마이그레이션 파일

`supabase/migrations/20261007100000_inquiries_budget_launch.sql` 은 예산·론칭일을 DB 의 별도 칸으로 나누고 싶을 때를 위한 **선택 사항**입니다. 지금은 적용하지 않았고, **적용하지 않아도 폼과 시트 알림은 그대로 동작합니다.** (현재 예산·론칭일은 DB `notes` 칸 첫 줄에 함께 저장됩니다.)
